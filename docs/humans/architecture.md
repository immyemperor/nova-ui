# Architecture

For maintainers and contributors. Read this before changing the packages.

## Packages

```
packages/
  core/      @omni/core     Stencil web components (71 in core), tokens, theme, utilities, i18n, docs generator
  editor/    @omni/editor   rich text editor (Tiptap), separate so Tiptap isn't a core dependency
  react/     @omni/react    generated React wrappers + hooks + page blocks; /editor and /server entry points
  angular/   @omni/angular  generated standalone proxies + ThemeService; /editor secondary entry point
  vue/       @omni/vue      Vue 3 wrappers generated from the manifest (scripts/generate.mjs)
  css/       @omni/css      layout, utilities, CSS-only components, print, guidelines; framework-free
  tailwind/  @omni/tailwind Tailwind preset mapping utilities to --nova-* tokens
apps/
  playground-vite/   React + Vite demo of every feature
  playground-next/   Next.js App Router demo
  playground-angular/ Angular standalone demo
docs/                user, human and agent documentation (this folder)
```

## Layers

1. **Tokens** (`core/src/global/tokens.css`, `css/src/tokens.css`). Colours, type, space, radius, shadow, motion, layout sizes, all as `--nova-*` custom properties. Single source of truth for every framework.
2. **Pure logic** (`core/src/utils/*.ts`, `core/src/i18n`, `editor/src/.../uploads.ts`). No DOM and no framework. Every rule that matters lives here so it can be tested in Node.
3. **Components** (`core/src/components/*`). Stencil web components. Each has a `.tsx` and a `.css`. Components use the logic layer and tokens; they don't hard-code colours or strings.
4. **Wrappers**. Generated for React, Angular and Vue from the component metadata. Hand-written only for hooks, helpers and blocks.
5. **Layout and utilities** (`css`). Independent of the web components. Usable on their own.

## Generated code: do not edit

| File | Generated by | Regenerate with |
| --- | --- | --- |
| `packages/react/src/components/stencil-generated/*` | `@stencil/react-output-target` | `pnpm build` |
| `packages/angular/src/lib/stencil-generated/*` | `@stencil/angular-output-target` | `pnpm build` |
| `packages/css/src/generated/utilities.css` | `scripts/generate-utilities.mjs` | `pnpm --filter @omni/css generate` |
| `packages/core/dist-docs/*` | `scripts/generate-docs.mjs` | `pnpm docs` |
| `packages/vue/src/components.ts` | `scripts/generate.mjs` | `pnpm docs` |
| `docs/llms-full.txt` | `scripts/build-llms.mjs` | `pnpm docs:agents` |

Change the source, then regenerate. CI fails if a generated file is out of date.

## Key design decisions

- **Web components, not framework components.** One implementation runs everywhere. The cost is that frameworks must map props and events, which the generators do.
- **Native elements where possible.** Dialogs use `<dialog>`; popovers use the Popover API (top layer, no clipping); forms use `ElementInternals` so controls submit natively.
- **Light DOM for the editor.** ProseMirror's selection, IME and spellcheck behave best outside a shadow root. The editor's CSS is prefixed so it can't leak.
- **No runtime animation library.** Motion uses the Web Animations API, CSS transitions and the scroll timeline. Everything respects `prefers-reduced-motion`.
- **Contrast is a build check.** Token pairs are measured against WCAG AA in both themes. The generator enforces the same rule for brand palettes.
- **Props never shadow DOM members.** `scripts/check-prop-names.mjs` checks all `@Prop` and `@Method` names against `HTMLElement`. (`Element.prefix` and `Element.getHTML` already caused bugs.)
- **Event names are `ui`-prefixed and kebab-cased in the DOM** (`ui-change`), camel-cased in frameworks (`uiChange`).

## Data flow for a value

User input → component updates its own state → emits `uiChange` with `detail` → framework wrapper forwards it as `onUiChange` (React), `(uiChange)` (Angular), or `@ui-change` (Vue). Form controls also call `setFormValue` on their `ElementInternals`, so native forms see the value without any code.

## Where things live

| Need | Look in |
| --- | --- |
| A component's behaviour | `packages/core/src/components/<name>/<name>.tsx` |
| Its styling | `packages/core/src/components/<name>/<name>.css` |
| The rules it uses | `packages/core/src/utils/<topic>.ts` |
| Its strings | `packages/core/src/i18n/messages.ts` |
| Its tests | `packages/core/test/<topic>.test.mjs` |
| Its docs | `docs/users/features/<area>.md` and the generated API reference |
